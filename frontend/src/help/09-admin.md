# Для администратора

## Пользователи

Раздел «Пользователи»: добавить (портал выдаст разовый пароль - он показывается один раз), открыть карточку
пользователя по логину и там:

- изменить имя, e-mail, Telegram, роль;
- **сбросить пароль** - выдаётся новый разовый, сеансы пользователя завершаются;
- **снять блокировку входа** после неудачных попыток;
- **отключить** - пользователь не сможет войти, сеансы завершаются.

Сброс пароля и отключение спрашивают подтверждение.

Себя администратор отключить или понизить не может: портал не должен остаться без администратора.

## Конфигурация установки

Всё, что относится к конкретной установке, задаётся в **файле проектов** установки (`projects.yaml`), а не в коде
портала:

| Раздел | Что задаёт |
|---|---|
| `projects.<код>` | Проект: название, репозитории тестов и результатов, разрешённые для запуска окружения |
| `projects.<код>.stands` | Стенды: описание, известная проблема и состав засева `seed_info` (Markdown), окружения тестов, адреса, доступы (`${ПЕРЕМЕННАЯ}` из файлов секретов), файл сведений о сборке, смоук после действий, команды действий и параметры пересборки |
| `help` | Блок «Документация и полезные ссылки» на «Обзоре» и страницы-инструкции (раздел «Эта установка» справки) |

Изменения файла проектов портал подхватывает без перезапуска.

## Обслуживание

### Обновления портала

Если служба обновлений настроена, она проверяет и устанавливает новую версию при своём запуске и каждый час.
В разделе [«Обновления»](/admin/updates), доступном администратору, показаны установленная и доступная версии,
время последней проверки и состояние операции. Кнопки «Проверить обновления» и «Установить обновление» позволяют
отправить запрос вручную.

Перед установкой служба ждёт завершения текущих задач и их дочерних операций, не прерывая их. Новые задачи
принимаются в очередь и начнут выполняться после обслуживания. При перезапуске портала страница автоматически
восстановит соединение и покажет результат. Если требуется ручное восстановление, установка заблокирована;
обратитесь к администратору сервера. Если служба не подключена, страница сообщает, что обновления не настроены.

Команды обслуживания выполняются на сервере портала (`python -m portal.cli ...` в контейнере портала):

| Команда | Что делает |
|---|---|
| `sync` | Обновить индекс прогонов и багов из репозиториев результатов |
| `user add <логин> --role <роль>` | Завести пользователя из консоли (например, первого администратора) |
| `user reset <логин>` | Задать пароль из консоли и снять блокировку |
| `user ensure-default-admin` | Создать admin со случайным паролем только при пустой таблице пользователей; пароль показывается один раз после сохранения, повтор ничего не меняет |
| `token add <имя> --role agent` | Выдать токен агенту |

## Токен для ИИ-ассистента

Ассистент (например, Claude Code на машине тестировщика) может разбирать прогоны, читая портал по API. Портал сам
ассистента не запускает и доступа в интернет не требует: ассистент работает у человека.

1. Выдать токен: `python -m portal.cli token add <имя> --role llm` (в контейнере портала). Токен показывается один раз;
   хранить у себя, не в git.
2. Ассистент передаёт его заголовком `Authorization: Bearer <токен>`.

| Что читает ассистент | Адрес API |
|---|---|
| Прогоны, итоги, список тестов прогона | `GET /api/runs?project=<код>`, `GET /api/runs/<id>` |
| Отчёт прогона - без блоков `ai-restricted`; прогоны в каталогах `restricted`/`sg-restricted` закрыты | `GET /api/runs/<id>/report` |
| Баги - без закрытой части | `GET /api/bugs?project=<код>`, `GET /api/bugs/<id>` |
| Статистика; стенды - что развёрнуто, состояние, проверка (без доступов) | `GET /api/stats`, `GET /api/projects/<код>/stands` |

Не получает никогда: Allure (сырые запросы и ответы), закрытые части багов и отчётов, доступы к базам стендов,
задачи и их логи (в логах действий со стендами бывают секреты), пользователей. Менять ничего не может. Правила закрытого - те же, что у `autotest.py view` движка тестов.
