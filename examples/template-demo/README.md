# Учебный шаблон с миграцией и smoke

API + SQLite в собственном Docker volume, повторяемые migrate/seed, два HTTP-теста,
JSON/JUnit/Allure. Runner и генератор отчёта выполняются отдельными контейнерами.
Исходники API и runner выбираются из разных refs одного локального учебного Git.

[Запуск, повтор и остановка](../../DEPLOY.md), [executor](../../stands/RUNTIME.md).
Не запускайте compose.yaml напрямую: `CONTEXT_SMOKE`, `OUTPUT_DIR`, проект и
ограничения ресурсов задаёт executor. Это учебный пример; для запуска через
очередь зарегистрируйте шаблон и репозитории в портале и локальном каталоге агента.
Standalone deploy-demo запускает тот же lifecycle напрямую.

Smoke сохраняет результаты даже при провале HTTP-проверок; его контейнер
возвращает 0, чтобы следующая обязательная команда создала HTML. Контейнер
reporter возвращает 1 при провале проверок и 2 при ошибке формирования отчёта.
Поэтому итоговая стадия smoke успешна только при успешных проверках и Allure.
При аварийном завершении runner стадия останавливается сразу, без ложного успеха.

Python и Node base tags могут обновляться. Snapshot закрепляет исходники, а
execution.json фиксирует ID полученных образов. Повтор сборки по SHA не обещает
побитово прежние образы при изменении базовых tags/пакетов в реестрах.
