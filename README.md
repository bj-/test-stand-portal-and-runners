# Test Stand, Portal and Runners

Переносимые инструменты для локальных тестовых окружений. Репозиторий начинается
с чистой истории: настройки конкретных установок, доступы и результаты хранятся
снаружи. Лицензия нового кода — [Apache-2.0](LICENSE).

**Запуск одной командой:** [развернуть портал и учебный стенд](DEPLOY.md).
`deploy.ps1` / `deploy.sh` устанавливают зависимости, запускают портал и пример
с миграцией, засевом, healthcheck и smoke/Allure. Сквозной lifecycle учебного
стенда принят на Windows Docker Desktop; чистые установки трёх ОС ещё не приняты.

## Что входит в первую версию

- [Локальный launcher портала](local/README.md): Python CLI для отдельного каталога
  установки, Compose, случайного пароля БД и сохранения данных при остановке.
  Код портала подключается из отдельного локального checkout через `--portal-source`.
- [Установщики ОС](installer/README.md): подготовка зависимостей и запуск портала
  на Windows, Ubuntu и macOS, продолжение после системных перезапусков.
- [Маленький HTTP-стенд и smoke runner](examples/http-smoke/README.md): нейтральный
  пример API и запуска проверок без подключения к клиентским системам.
- [Контракт шаблона и подготовка исходников](stands/README.md): проверка состава,
  локальные Git refs, отдельные контексты и повтор по сохранённым SHA.
- [План развития](docs/plan.md): шаблоны, выбор веток, создание стендов из интерфейса,
  локальные агенты и управление временем жизни.

В портале доступен мастер создания стенда из зарегистрированного шаблона;
очередь исполняет `stands.worker` через локальный [Compose executor](stands/RUNTIME.md).
Продуктовый адаптер и обычные test-engine прогоны динамических окружений ещё нужны.
Подготовка по refs читает существующие локальные clones без fetch.
Код портала и его лицензия остаются в отдельном проекте `test-portal`;
наличие этого репозитория само по себе не предоставляет доступ к его исходникам.

## Требования

Установщики в [installer/](installer/README.md) подготавливают Python, Git и Docker,
затем запускают локальный портал. Установка не требует LLM: команды, продолжение
после перезагрузки и диагностика описаны в инструкции. Исходники портала нужно
получить отдельно и передать через путь `--portal-source` / `-PortalSource`.

Среда выполнения: Python 3.12+, Docker с Compose v2. Для Windows/macOS — Docker Desktop с Linux
контейнерами, для Ubuntu — Docker Engine и Compose plugin.
Команды одинаковы на всех трёх ОС; фактическая контейнерная приёмка на каждой
платформе отмечается отдельно в [статусе](docs/STATUS.md).

Перед запуском прочитайте README выбранного компонента: настройки и результаты
нужно размещать вне каталога этого репозитория. Для нового стенда нужны отдельные
порты и имя Compose-проекта.

## Разработка

Проверки каждого компонента и команды запуска описаны в его README. Python-код
первого комплекта использует стандартную библиотеку. Необходимость Docker
отделена от unit-тестов: отсутствие Docker не выдаётся за успешный запуск стенда.

## Структура

| Каталог | Назначение |
|---|---|
| `installer/` | Установка зависимостей и запуск портала без LLM |
| `local/` | Управление локальной установкой портала |
| `stands/` | Контракт шаблона, Git SHA, Compose executor и host-worker |
| `examples/template-demo/` | Учебный lifecycle с SQLite и smoke/Allure |
| `examples/http-smoke/` | Нейтральный маленький стенд и runner |
| `docs/` | План, состояние и журнал проекта |

Этот репозиторий не содержит клиентских адресов, каталогов репозиториев,
учётных данных, сертификатов, резервных копий или истории прежних установок.
