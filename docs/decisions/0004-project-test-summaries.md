# 0004. Сводки тестирования на уровне проекта

- **Статус:** принято
- **Дата:** 2026-11-27
- **Участники:** bj, Codex

## Контекст

Сводка оценивает покрытие и готовность модуля по нескольким источникам. У нее есть дата среза, но она не принадлежит одному прогону и не должна менять данные отчетов, Allure или статистики.

## Решение

Отдельный раздел «Сводки» фильтруется по проекту. На дашборде выбранного проекта есть плашка с последней сводкой и входом в историю. Источник - датированный каталог `summaries/<id>` в клоне результатов либо `project-summaries/<код>/<id>` под `PORTAL_ARTIFACTS`. При совпадении ID клон результатов имеет приоритет. Манифест и Markdown обязательны, автономный HTML необязателен.

Portal показывает Markdown и отдает файлы на скачивание, не исполняя презентацию на своем origin. Применяются роли чтения прогонов. Закрытые блоки не попадают в выдачу метаданных и Markdown, токен LLM не получает презентацию. Сводки не импортируются в БД и не меняют статистику.

## Альтернативы

Вкладка у одного прогона скрывает зависимость от других версий, результатов и внешних артефактов coverage. Хранение в БД потребовало бы отдельного редактора, прав записи, миграции и механизма переноса истории. Файловый комплект поддерживает и Git-историю, и установки без клона результатов.

## Последствия

Доступность сводок зависит от доставки комплекта в хранилище установки. Старые отчеты без манифеста остаются на месте. Формат, шаги сборки и публикации описаны в [справке](../../frontend/src/help/12-project-summaries.md).
